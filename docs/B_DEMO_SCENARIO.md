# 2차 PT 앱 B 시연 시나리오

이슈 #36 중 **앱 B의 화면·시연 동선**을 정의한다. 서버 실행, 시연 계정·데이터 생성, APK 설정은 서버/앱 C 담당과 함께 최종 확인한다. 이 문서가 전체 이슈의 완료를 의미하지는 않는다.

## 반영된 화면과 리허설 전제

아래 시나리오는 최신 운전자 선택 UI를 기준으로 한 **통합 리허설 절차**이다. 실행 전 사용한 main 커밋과 APK 빌드 시각을 기록한다. 코드·자동 테스트 확인과 서버까지의 실연 완료는 구분한다.

- 선택 안내 위 중앙 검색바 → 검색 모달에서만 이름 검색. 닫으면 입력 초기화, 메인 프로필 목록은 검색어로 필터링하지 않음
- 최근 운전자 최대 5명과 추가 버튼, 첫 화면의 `더보기`, 화면 아래 추가 프로필과 끝의 `접기`
- 왼쪽 위 `프로필 관리` → 이미지의 수정/삭제, 관리 중 추가 버튼 없음, 흰색 `완료`
- `프로필 생성`/`프로필 수정` → 이름·색상·표정·캐릭터, 아래 고정 영역의 **선택** 위치 동의. 미동의여도 저장 가능; 편집에서 철회 가능
- 운행 시작은 프로필 선택 → `주행 시작`. 나중에 선택하기·부서 입력 없음
- 차량 연결은 선택 화면 아래 카드. 운행 종료 후 최근 운행에서 `운행 확인` → 목적 저장
- D에서는 프로필·거리·시간을 표시하는 읽기 전용 `운행 현황`. 검색·편집은 제거되며 P와 플랫폼 제한 해제 확인 후 복귀

## 시연 전 준비

| 담당 | 준비물 | 통과 기준 |
| --- | --- | --- |
| 서버 | 독립된 시연용 회사·차량·관리자 | 실사용 데이터와 구분되고 관리자 로그인이 가능함 |
| 서버 | 승인 운전자 1명, 승인 대기 운전자 1명 | 이름과 승인 상태로 구별 가능하며 서버에 반영됨 (앱에는 부서 입력 없음) |
| 서버 | 업무 목적 목록 | 미팅·물품 수령 등 회사에 맞는 항목을 준비함 |
| 앱 C | debug APK와 서버 주소 | PC는 `127.0.0.1`, 에뮬레이터는 `10.0.2.2`, 포트 일치 |
| 앱 A | Pleos 차량 값 | P 기어와 0보다 큰 누적거리 수신 확인 |
| 앱 B | 기본 흐름과 예외 화면 | 아래 정상 흐름과 상태별 안내를 실제 기기에서 확인 |

서버 절차는 [ANDROID_LOCAL.md](https://github.com/FrameMayoChuatang/AutoLog-server/blob/main/docs/ANDROID_LOCAL.md), 데이터·페어링 규칙은 [API.md](https://github.com/FrameMayoChuatang/AutoLog-server/blob/main/docs/API.md)를 기준으로 한다.

1. 서버 저장소에서 `docker compose up -d --wait` 후 `./mvnw spring-boot:run -Dspring-boot.run.profiles=emulator`를 실행한다.
2. PC에서 `curl http://127.0.0.1:8080/actuator/health`의 UP 응답을 확인한다.
3. Pleos Connect API 34 에뮬레이터를 독립 창으로 연다.
4. 앱 저장소에서 JDK 17 또는 호환되는 Android Studio JBR로 `./gradlew :app:assembleDebug -PserverUrl=http://10.0.2.2:8080 -PconsoleOdometer=true`를 실행한다. 콘솔 거리 옵션은 현재 벤더 이미지 전달 오류가 있는 에뮬레이터 시연에만 사용하며, 기본/Release 빌드는 SDK 경로다. 자세한 실행·모의 주행은 [DEMO_ENVIRONMENT.md](DEMO_ENVIRONMENT.md)를 따른다.
5. `adb shell am get-current-user`로 현재 사용자를 확인하고, `adb install -r --user <현재 사용자> app/build/outputs/apk/debug/app-debug.apk`로 업데이트한다. 기존 기록을 보존하기 위해 앱 데이터 초기화나 재설치는 하지 않는다.
6. `adb shell am start --user <현재 사용자> -n com.framemayo.autolog/.ui.MainActivity`로 실행한다.
7. 관리자는 **시연 직전** 새 8자리 페어링 코드를 발급한다. 코드는 기본 10분 만료·1회용이며, 앞의 0을 유지한다. 토큰·비밀번호를 문서나 녹화 화면에 남기지 않는다.

## 기본 시연: 연결 → 기록 → 확인

| 순서 | 화면·행동 | 확인할 결과 |
| --- | --- | --- |
| 1 | 미연결 상태에서 프로필 선택 → `주행 시작` → 안내창의 `차량 연결하기` | 시작을 차단하고 선택 화면 아래 페어링 카드로 이동 |
| 2 | 8자리 코드 입력 → 연결 | 차량 정보 표시, 연결 전에는 운행 시작 불가 |
| 3 | 승인된 운전자 프로필 선택 → `주행 시작` | P·유효한 누적거리·연결 상태 확인. 동의가 true면 바로 시작, 미응답/미동의이면 해당 안내 표시 |
| 4 | 미응답은 `동의 안 함` → 경고창 `동의 없이 시작`, 기존 미동의는 경고창에서 `동의 없이 시작` | 거리·시간 기록 시작, 업무 도착 위치 수집 안 함. 별도 리허설에서 `동의`/`동의하고 시작`과 Android 권한 요청도 확인 |
| 5 | D로 변경 후 콘솔 누적거리 증가 또는 개발용 모의 주행 스크립트 사용 | 읽기 전용 운행 현황에서 프로필·거리·시간 증가, 검색·프로필 편집 없음. 모의 거리는 실측 정확도 검증이 아님 |
| 6 | P에서 `운행 종료` | 종료 후 기록 화면 유지, 최근 운행에 새 기록 표시 |
| 7 | 최근 운행의 `운행 확인` → 목적 선택 → `목적 저장` | 한국어 분류 표시, 전송 상태 확인 가능 |
| 8 | 관리자 화면에서 같은 기록 확인 | 운전자·시작/종료 누적거리·분류·확인 상태 일치 |
| 9 | 앱에서 `확인 및 수정` → 다른 목적 저장 | 새 선택이 서버에 재확인됨. 이미 승인된 기록은 관리자 확인 필요 |

업무 세부 목적은 #83에서 회사 목록 선택 또는 직접 입력 후 메모와 분리해 저장·전송한다. 운행은 프로필 선택으로 시작하며, 부서 입력은 제공하지 않는다. 실제 서버를 통한 통합 시연 완료 여부는 아래 리허설 기록으로 별도 관리한다.

## 예외 시연: 한 번에 한 조건만 변경

| 조건 | 동작 | 화면·서버 확인 |
| --- | --- | --- |
| 승인 대기 운전자 | PENDING 프로필로 종료 후 목적 저장 | `전송 보류`와 관리자 승인 대기 이유 표시; 승인 후 확인 전송 |
| 기존 운전자 미지정 기록 | 운행 확인 → 운전자 지정 → 검색 → 지정 확인 | 지정 전 경고, 지정 후 변경 버튼 없음; 목적이 이미 있으면 확인 전송 |
| 목적 미확인 | 측정값만 서버로 전송 | `전송 완료`라도 목적 선택이 필요하다는 안내 유지 |
| 오프라인 | 테스트 서버 일시 정지 후 기록 종료 | 앱이 종료되지 않고 전송 대기; 서버 복구 후 자동 재전송, 중복 없음 |
| 서버 거절 | 시연용 승인·잠금 기록에 수정 시도 | `전송 실패`와 수정/관리자 확인 안내. 무한 재시도하지 않음 |
| 차량 미연결 | 시연용 차량 연결 해제 | 프로필을 누르면 연결 안내, 운행 시작 차단, 새 코드로 재연결 가능 |
| 중단된 운행 | 준비된 INTERRUPTED 기록 확인 | `중단됨`과 실제 종료값 확인 필요 안내; 정상 완료로 오인하지 않음 |
| 프로필 수정·삭제 | 이름 수정 후 과거 운행 확인, 별도 프로필 삭제 | 표시 이름 일치; 삭제 프로필은 지정/동의 선택 목록에서 제외, 과거 기록 보존 |
| 주행 상태 | 검색/편집 모달이 열린 상태에서 D로 변경 | 모달·키보드 제거, 읽기 전용 운행 현황. P·수집 정상·제한 해제 확인 후 편집 복귀, 이전 모달은 다시 열리지 않음 |
| 제한 정보 수신 실패 | API 미지원/연결 실패가 재현되는 검증 환경 | 입력 잠금 사유 표시. 정상 수신한 P에서는 `제한 정보 다시 연결`; D에서는 재연결도 노출 안 함. 재요청 자체로 잠금이 풀리지 않음 |
| 프로필 동의 | 생성에서 미체크 저장, 편집에서 동의 후 철회 | 생성 차단 없음; 저장 후 동의 상태 유지, 철회하면 해당 운전자의 기기 내 도착 위치 삭제 |
| 프로필 탐색 | 6명 이상 준비 → 더보기 → 아래 스크롤 → 접기 | 맨 위에서 추가 프로필은 숨김, 더보기는 표시. 펼친 뒤 추가 목록 확인, 접기 후 최근 목록 복귀 |

서버 정지·토큰 폐기·강제 종료는 시연 전용 환경에서 별도 수행한다. #40의 실제 종료값 복구는 앱 A 담당이며 B 화면 작업으로 완료 처리하지 않는다.

## 리허설 기록

아래 항목은 담당자가 실제로 확인한 뒤 체크한다. Compose 자동 테스트는 실제 서버·Pleos 통합 시연을 대체하지 않는다.

- [ ] 사용한 앱 커밋 / APK 빌드 시각 기록
- [ ] 사용한 서버 커밋 / 실행 포트 기록
- [ ] Pleos 이미지 / 기어·누적거리 수신 확인
- [ ] 정상 흐름 1~9 완료
- [ ] 승인 대기·오프라인·서버 거절·미연결 상태 확인
- [ ] 이름 수정·숨김과 검색·지정 확인
- [ ] 재실행 후 운행·프로필 보존 확인
- [ ] 실제 발표 화면에서 글씨·터치 영역·모달 스크롤 확인
- [ ] 녹화/스크린샷에서 비밀번호·토큰·개인정보 제거 확인

서버 health가 UP이어도 위 정상·예외 시연이 모두 완료됐다는 뜻은 아니다. 서버 반영까지의 전체 리허설과 토큰 폐기/재페어링 검증은 별도로 기록한다. 토큰 폐기는 백엔드·앱 C 담당과 시연 전용 환경에서 수행하며 운영 계정에 적용하지 않는다. 전체 #36 완료는 각 담당자의 준비와 위 체크를 마친 뒤 판단한다.
